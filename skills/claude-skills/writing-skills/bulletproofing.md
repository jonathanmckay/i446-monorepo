# Bulletproofing a Discipline Skill

Part of `writing-skills`. Adapted from obra/superpowers (MIT).

For skills whose failure mode is "the agent knows the rule and skips it under
pressure" (no points logged for a bare `[N]`, no fix before a root cause,
never send as JM). For wrong-shaped output or omissions this toolkit
backfires; use a recipe or a template instead.

## Close every loophole explicitly

Do not just state the rule; forbid the specific workarounds.

```markdown
A bare [N] while a task is claimed is that task's VALUE, not a completion.

No exceptions:
- Do not log it "provisionally".
- Do not run /did "to be safe".
- Do not treat JM's "nice" as a completion.
```

## Cut off "spirit versus letter"

Put this near the top: *Violating the letter of the rule is violating its
spirit.* It removes a whole class of "I'm following the intent" arguments.

## Keep a rationalization table

Every excuse the agent has actually used goes in, with the reality beside
it. Seed it from observed failures, not imagination.

```markdown
| Excuse | Reality |
|---|---|
| "Too simple to need the process" | Simple cases have the same failure. The process takes a minute. |
| "I'll verify after" | Verification after a claim is the thing /forreal exists to catch. |
```

## Add a red-flags list

Short phrases the agent can match against its own thinking, ending with the
one instruction that applies to all of them.

```markdown
## Red flags: stop
- "Quick fix for now"
- "I already checked this manually"
- "This case is different because..."
All of these mean: back to Phase 1.
```

## Put the violation symptoms in the description

The description should name the moment the rule is about to be broken, so
the skill loads then: "before proposing any fix", "when about to log points
for a claimed task".
